# CMS v1.7.3 探针故障复盘与开发规范

## 背景

v1.7.1加入加载探针后，出现知识页偶发空加载。

最终发现：

不是CMS业务逻辑错误。

而是调试探针自身错误。

------------------------------------------------------------------------

# 根因

错误：

    dbgUi("loadMem", params.xxx)

但是：

函数作用域不存在：

    params

导致：

    ReferenceError
     ↓
    catch
     ↓
    加载失败重试
     ↓
    memory加载失败
     ↓
    空状态

------------------------------------------------------------------------

# 为什么dbgUi保护无效

因为：

函数参数会先求值。

例如：

    dbgUi(
     "loadMem",
     params.id
    )

执行顺序：

    计算params.id
     ↓
    报错
     ↓
    dbgUi尚未执行

所以：

dbgUi内部try无法捕获。

------------------------------------------------------------------------

# 修复

v1.7.3：

1.  params改为真实存在变量
2.  全量检查探针变量
3.  增强debug安全性（dbgUi 内置 try 保险）

------------------------------------------------------------------------

# 调试代码规范

## 1. 探针不能影响业务

错误：

    业务
     ↓
    debug构造失败
     ↓
    业务失败

正确：

    业务
     ↓
    debug失败
     ↓
    继续运行

------------------------------------------------------------------------

## 2. 避免复杂参数表达式

不要：

    dbg(JSON.stringify(obj.xxx))

推荐：

    safeString(obj)

------------------------------------------------------------------------

## 3. 调试系统也是生产路径

日志代码同样需要：

-   变量检查
-   try保护
-   最小副作用

------------------------------------------------------------------------

# CMS最终架构

    数据层
     ↓
    缓存层
     ↓
    生命周期加载
     ↓
    state
     ↓
    render纯函数
     ↓
    UI

不要：

    render
     ↓
    修正数据
     ↓
    触发render
